# Vaults

## Input

The selected vault, lane, or note and its established organization.

## Workflow

Locate the real topic owner before writing. Root and lane entrypoints provide
purpose, navigation, and working rules; notes own durable explanations.

| Entrypoint | README | AGENTS |
| ---------- | ------ | ------ |
| Root | [README](../assets/templates/obsidian-root/README.md) | [AGENTS](../assets/templates/obsidian-root/AGENTS.md) |
| Lane | [README](../assets/templates/obsidian-lane/README.md) | [AGENTS](../assets/templates/obsidian-lane/AGENTS.md) |

Preserve existing names, links, and organizational method. For a requested new
PARA vault, projects own bounded efforts, areas ongoing responsibilities,
resources reusable knowledge, and archives inactive material. An inbox holds
unclassified capture; it is not a substitute for an established owner.

## Output

Verified knowledge integrated in its topic owner with usable navigation.

## Rules

- Creating entrypoints does not authorize reorganizing the vault.
- Use filesystem-resolvable links for agent-facing navigation.
- Follow the caller's writing style and existing note format.
